# 小眾定位與體驗原型計畫

> 2026-10-10。目的：先服務一個小眾、做出一條完整的學習循環，自己當第一個使用者實際練習，再決定要往哪個體驗方向擴大。

## 1. 結論

### 市場觀察（摘要）
- **課程優先**（Speak / Babbel / Duolingo）：短課 → 跟讀練習 → AI 角色扮演 → 複習。常見批評：課程、自由對話、複習三塊沒有串起來；程度越高越重複。
- **對話優先**（Loora / Talkpal / Langua）：直接選情境聊，結束後給分數與報告。常見批評：不知道要聊什麼、AI 重複、跨次記憶不穩。
- **遊戲化優先**（Duolingo）：路徑、連續天數、能量制。免費版練習量受限，練習與真實對話落差大。
- 趨勢：學完立刻用、AI 記得你（Duolingo Video Call 會從剛學的主題開聊，並記得上次聊了什麼）。

### 我們不做什麼
- 不拚語音 / 視訊角色、不拚課程量、不拚語言數量。
- 不一開始追求大市場。

### 小眾定位
**母語是中文、在工作或生活中需要「用英文說出自己的看法並講出理由」的 B1–B2 學習者。**

- 痛點：會說 I think…，但接不出理由、講到一半卡住、句子散。
- 第一個使用者：專案作者本人。
- 為什麼是這群人：需求明確（會議、面試、跟外國朋友聊天）、國外 app 很少用中文解釋常見錯誤（例：`due to` 後面接句子、`so` / `so that` 分不清）、我們已有中文介面與母語解釋。

### 核心差異：一條串起來的循環
```
章節學連接詞 → 在 AI 朋友對話中真的用出來 → 朋友語氣的回饋（只肯定真的用到的）
      ↑                                                        ↓
   隔天的題目 / 日記又出現 ←──────── 用過的句子進單字庫（SRS）
```
零件現在都有（章節、情境、角色記憶、日記、SRS），缺的是串接。

## 2. 第一個內容：「說出你的理由」章節

`frontend/src/data/chapters/en/intermediate/09-giving-reasons.yml`

- 三步驟結構：先講看法 → 給理由 → 收尾或反問
- 原因與結果：because / since / due to / because of / as / so / which is why
- 目的：in order to / to / so that
- 補充理由：another reason is / plus / also / on top of that
- 每個條目附中文說明與常見錯誤；例句皆為原創

## 3. 三個體驗原型（各開一個 worktree / branch）

三個版本用**同一份章節內容**，只差在「使用者怎麼走完一輪」。都只改前端，不改後端 API，方便直接比較。

| | A. 課程優先 | B. 對話優先 | C. 每日微任務 |
|---|---|---|---|
| Branch | `proto/a-lesson-first` | `proto/b-chat-first` | `proto/c-daily-drill` |
| 入口 | 學習頁 → 章節 | 首頁 →「跟朋友聊聊你的看法」 | 首頁卡片「今日觀點（3 分鐘）」 |
| 流程 | 讀卡 → 填空題（含錯誤解釋）→ 「去聊天用用看」帶著 3 個目標詞進情境對話 | 朋友丟一個話題 → 你回答 → 沒給理由時朋友自然追問 why → 輸入框上方即時連接詞提示 → 結束時總結用了哪些 | 一題日常問題 → 用三步驟寫 / 說一段回答 → 朋友回饋並標出用到的連接詞 → 好句子存進單字庫 |
| 練到的 | 正確用法 | 臨場說出口 | 每天固定量、累積 |
| 風險 | 像上課、可能不想進聊天 | 程度不夠時會卡住 | 單次太短、缺少來回 |

### 共用的「目標詞偵測」
前端用比對找出使用者訊息裡出現的本章連接詞（不需改後端），用於：即時標記、對話結束總結、回饋語氣（「你用了 since，很自然！」）。

## 4. 怎麼比較

自己每個版本各用 3 天（或連續各練 3 輪），每輪結束記錄：

1. 有沒有想再練一次？（1–5）
2. 這輪實際用出幾個不同的連接詞？
3. 卡住的地方在哪裡？
4. 隔天還記得哪幾個？

結果寫回本文件第 5 節，再決定合併哪個版本（或混合）。
